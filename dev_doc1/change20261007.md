# 2026-10-07：清晰预览与大图按需解码

## 目标与统一原则

图片在最小倍率下按**图片显示区的物理像素尺寸**生成预览；放大或移动后，重新从源文件读取当前可见的原图区域，按当时的显示倍率生成新的位图。不能把最初的缩小预览反复放大当作清晰图像。解码出的整图像素数或文件大小超过阈值时，主窗口只保留有界的预览和当前视口位图，不常驻完整原分辨率位图。这套显示原则对所有已支持的图片格式一致，具体读取方法由文件内容和解码器能力决定。

最小倍率由视口尺寸和原图尺寸计算。`MainWindow.PreviewPixelSize` 把 WPF 显示尺寸换算为 DPI 物理像素，最多用 1.5 倍采样，并限制预览的额外像素预算。打开时直接按该目标尺寸请求预览；窗口尺寸改变且现有预览像素不足时，重新向原文件请求更大预览。图片放大后，`RenderAsync` 用滚动偏移、当前倍率和视口宽高计算原图坐标中的 `Int32Rect`；`ImageLoader.LoadRegionParallelAsync` 读取该矩形并缩放到实际显示分辨率。旋转时先把显示坐标的矩形映射回源图坐标，再旋转有界的输出。源文件消失或读取失败时返回真实错误，不把旧缩略图冒充已经读取的新区域。

## 所有格式的解码选择

1. **识别内容与尺寸。** `ImageLoader.Load` 读取文件签名、解码器元数据、文件大小和像素尺寸；不能仅凭文件扩展名决定格式。大文件阈值和 3200 万解码像素阈值中的任一个命中，就走有界显示路径。小图可走普通完整位图路径。
2. **原生区域读取。** 对报告 `PARTIAL` 能力的解码器，直接读取可见区域。TIFF 等多级图在缩小时，可选择仍足以覆盖目标显示像素的较低金字塔层；其余格式按解码器提供的区域能力读取。这样避免为很小的屏幕区域解码整张原图。
3. **顺序读取。** 没有原生区域能力时，libvips 以 `Sequential` 和 `memory: false` 打开文件，先从源图裁出可见区域，再缩放和旋转裁剪结果；预览则在顺序读取流水线中缩小到显示目标尺寸。这条路径可能必须从文件开头扫描到所需行，但不把整张原图展开后留在托管内存。
4. **解码器回退。** libvips 无法处理的格式尝试 Magick.NET。回退先按文件内容识别格式，设置像素缓存的内存、面积、磁盘和线程限额；区域显示从原图解码后裁剪、缩放，因此清晰度仍以源图区域为准。此路径依赖各格式解码器的实际行为，不保证所有文件都能在相同资源和时间内完成。
5. **PSD/PSB 复合图。** 文件签名为 `8BPS` 且复合图布局受支持时，`PsdCompositeReader` 直接读取合并图，而不加载全部图层。未压缩和 PackBits 数据使用行偏移访问；ZIP 和 ZIP 预测数据顺序解压并逐行丢弃已经处理的行。按目标像素累计多个源样本进行缩小，输出大小受限。布局不受支持时使用通用回退解码器。PSD/PSB 是格式专用加速，预览与放大仍服从同一显示原则。

上述路径不能让不支持随机访问的压缩格式突然具备常量时间区域读取。顺序扫描也可能耗时；某些原生解码器还可能在应用像素缓存限额以外分配内存。资源不足、损坏文件或没有可用解码器时，应明确报告失败，而不是承诺任意尺寸、任意格式必定打开。

## 异步、取消与内存

打开、刷新预览和区域渲染在后台任务运行。每次任务携带取消令牌及窗口的图像代数；用户停止工作、切换图片或改变倍率后，过期结果不能替换当前图像。PSD 行读取定期检查取消令牌；libvips 管线登记进度与停止信号。第三方解码器的单次原生调用可能无法立即中断，其取消响应受解码器限制。预览、区域位图和 PSD 行缓冲均有独立大小限制；libvips 并发线程数限制为 2 至 4，Magick.NET 也设置进程级资源限额。

## 调用关系

`MainWindow.OpenAsync` → `ImageLoader.Load` → 初始显示尺寸预览；
`MainWindow.QueueRender` → `RenderAsync` → `ImageLoader.LoadRegionParallelAsync` → 原生区域 / 顺序区域 / Magick.NET 回退；
最小倍率下预览像素不足时，`RefreshPreviewAsync` → `ImageLoader.LoadPreview`；
PSD/PSB 支持的复合图由 `PsdCompositeReader.Inspect`、`LoadPreview` 和 `LoadRegion` 处理。

主要实现文件：`TANGERINE-PhotoViewer/MainWindow.xaml.cs`、`TANGERINE-PhotoViewer/ImageLoader.cs`、`TANGERINE-PhotoViewer/PsdCompositeReader.cs`。解码限制与故障边界另见 `dev_doc1/Large_Image_Decode_Fallback.md`。

## 2026-10-07：笔记保存与全链路核对

笔记导出必须重新读取原图，不能借用屏幕预览位图。原先 PSB 可以通过 `PsdCompositeReader` 打开、缩放，却在保存时进入 `AnnotationExport.SaveWithVips`，由 libvips 再次打开源文件；libvips 不识别该 PSB，因此报 `ANNS0003`。通用 Magick 回退还被源文件大小阈值拒绝，导致笔记无法保存。

现在导出器先按文件内容识别 Photoshop 合成图。受支持的 PSD/PSB 通过 `PsdCompositeReader.WriteInterleavedRgba` 逐行解码成临时 RGBA 像素文件，libvips 的 `Rawload` 从该文件按需读取、叠加笔记并编码。未压缩与 RLE 合成图按行定位；ZIP 与 ZIP 预测合成图顺序解压，以磁盘临时文件合并颜色通道。托管内存不容纳整张原图；取消或失败时清理临时文件。此路径输出合成图，不保留 Photoshop 图层，因此保存对话框默认提供 PNG。对于非常大的 PSD/PSB，完整分辨率导出仍需要足够的临时磁盘空间与编码时间，这和仅显示当前视口的打开、放大操作不同。

对其他格式，导出器先尝试 libvips 的流式读写；读写器不支持时交给 Magick.NET，由其像素缓存限制内存并在需要时使用磁盘。多页与 TIFF/GIF 的关键分支按文件内容或解码器元数据选择，而不是仅按输入文件后缀选择。保存后使用输出元数据校验分辨率；PSD/PSB 源尺寸使用已解析的合成图头，避免再次交给不支持它的库。目录图片扫描也纳入 Photoshop 合成图读取器，支持切换到 PSB。

逐条核对的调用链为：`OpenAsync` → `ImageLoader.Load`；最小倍率预览 → `LoadPreview`；放大与移动 → `LoadRegionParallelAsync`；目录切换 → `CanDecode`；GIF 帧导出 → `ExportGif`；笔记保存 → `AnnotationExport.SaveAsync` → 格式对应的解码和写入路径。放大路径仅使用现有的 `Resize`、裁剪和旋转 API；原生区域能力由 libvips 报告的 `PARTIAL` 标志决定，不推断格式一定具备该能力。编译检查不能证明每一种第三方格式和极端大文件都已在真实文件上运行成功；按要求不进行冒烟测试。
