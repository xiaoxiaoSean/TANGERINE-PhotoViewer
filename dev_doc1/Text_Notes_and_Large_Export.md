# 文字笔记与大图导出开发文档

## 功能与交互

“笔记”菜单增加“文字”。右键点击“文字”弹出设置窗口，可选择字体、相对字号、颜色、加粗、阴影与阴影大小。颜色支持直接输入六位十六进制 RGB 值，也提供常用颜色按钮。画笔选项窗口同样支持十六进制输入与常用颜色选择。两个工具菜单以当前颜色显示文字，背景为 RGB 各通道反色。

左键选择“文字”进入编辑模式，顶部第一个菜单显示“你正在编辑，‘文字’工具正在使用”。用户在图片上拖出矩形后，矩形高度决定实际字号，设置窗口中的相对字号为矩形高度的 10%–100%。横向或纵向长度为零时，左下角显示“你画出的空间不可添加文字”，不建立文字对象。矩形建立后输入框获得焦点并预填 `Text`；宽度不足时只预填能容纳的前缀，若一个字符也放不下则删除矩形并显示“矩形太小”。

用户可继续输入和选择文字。选择非空范围时，顶部“切换工具”右边出现“文字设定”。该窗口可以修改选中文字的字体、字号、颜色、加粗、阴影等属性。选区字号的下限为 1 源图像素，上限由当前矩形的高度和可容纳一个字形的宽度共同限定；窗口实时显示当前值和最大值。点击“完成”只把属性应用于选区，其他文字的字号和格式保持原样。普通的图片滚轮移动、缩放和鸟瞰图继续沿用原有交互。文字编辑器取得键盘焦点时，方向键用于移动光标或选择文字，不切换图片。

完成文字矩形后，顶部另提供“文字字号”，用于调整整块文字的基础字号，范围从 1 源图像素到当前矩形高度与单个字形可容纳宽度共同限定的最大值。选区中单独设置的字号作为各段文字属性保留，并在原分辨率导出时分别栅格化。鼠标进入矩形内部或接近边界时显示边框和四个实心圆角点。拖动右下角缩放矩形，拖动其余角点或边框移动矩形；缩放时若旧字号超出新矩形上限则自动收紧，选区字号也限制到新上限。移动与缩放同步改变屏幕编辑框、阴影预览及另存为所用的源图位置。

鼠标进入矩形内部就显示编辑框，并用半透明黑色压暗矩形内部，以便从背景中辨认文字范围。四条边框从当前显示的图片中只采样可见的一像素宽条带，再将每个条带像素的 RGB 分量分别取反；因此边框沿途每一点都与其背后的图片颜色相反。采样范围裁剪到滚动视口，内存开销随屏幕可见边长变化，与原图像素总数无关。四个角点保持实心圆；边框与压暗层仅用于编辑界面，不进入另存为图像。鼠标移出矩形时隐藏框，滚动、缩放、旋转或大图区域刷新时更新反色条带。

缩放滑块的悬停百分比使用黑底白字提示。字体下拉列表的普通、悬停和选中项分别由控件模板明确绘制为黑色或深灰背景与白字，避免系统主题覆盖选中背景。可编辑字体输入框的实际模板部件也设置为黑底白字，文本选区使用深蓝底色，保证选中输入内容可读。两个弹出层不能依赖父窗口的前景色继承，因为 WPF 会为弹出层采用系统默认背景。

## 像素、异步与状态

文字在编辑阶段保持可修改；另存为时由后台 STA 工作线程按导出器请求栅格化最多 256×256 源图像素的区域，再与画笔位图块一起按原图像素坐标合成。导出的宽高始终来自源图，而不是屏幕预览或编辑器尺寸。文字编辑器的布局边长限制在 2048 界面单位以内，再用变换恢复原图坐标；选区阴影预览使用最多约 420 万像素的后台位图，极大矩形会降低预览采样密度，导出仍按源图像素分块生成。文字渲染进度和保存进度分别登记，两个任务同时进行时左下角以“正在甲 xx%|正在乙 yy%”显示。打开图片、准备缓存和读取区域也使用相同的任务进度登记，避免一个回调覆盖另一个任务状态。

为修复小图另存为停在 0% 且没有新文件的问题，导出器先用 libvips 读取页数；成功读取而没有多页字段时直接按单页处理，只有 libvips 无法读取时才对受大小限制的文件使用 Magick 回退。导出工作线程启动及格式判定完成后分别上报进度。文字图层将相交的文字矩形合并、相距较远的矩形分开；每组不超过约 420 万像素时在后台直接生成一块有界 RGBA 图层，较大范围在系统临时目录生成稀疏 RGBA 原始像素文件，并让 libvips 通过 `rawload` 惰性读取。逐块写入只占用有限内存，透明空白区域保持文件空洞。这样在大图两端各放一处文字时，不必生成覆盖两处之间整片空白区域的透明层。所有图层按原图坐标合成，另存为仍使用原图分辨率。

另存为成功后，左下角以本土化文字显示“另存为”任务完成；若文字渲染也参与，两个任务的最终状态按“文字渲染已完成|‘另存为’任务完成”的形式显示。打开图片、缓存准备、区域读取和 GIF 帧导出也在工作结束后切换为“某任务已完成”，运行中最高显示 99%，不会停留在 100%。并发任务始终由同一个状态栏用竖线分隔；失败或取消则显示对应终态。

导出前冻结笔记块，后台线程负责解码、叠加、编码和输出尺寸检查。`AnnotationExport` 将 libvips 缓存与并发量限制在有界范围内，使用一次叠加运算处理所有块，避免每个块都生成一条覆盖整图的处理链。对较大的 TIFF 启用 BigTIFF，并为尺寸一致的多页 TIFF 保持流式处理。源图与输出的像素深度、通道数量及元数据尽量维持原有值，具体仍受目标编码器支持范围限制。

不支持安全流式处理的超大多帧格式，以及页尺寸不一致的 TIFF，应以 `ANNS0002` 提示格式不支持，不能回退到可能一次性载入所有帧的路径。写入失败使用 `ANNS0003`，输出尺寸或页数检查失败使用 `ANNS0004`。临时输出文件只在验证完成后替换目标。先前大文字区域使用 PNM 流，但发布包运行时无法找到 `ppmload_source`，会在真正保存前立即报 `ANNS0003`。现已移除该操作及整个 PNM 流类，改用 `rawload`；RGBA 临时文件先通过 Windows 稀疏文件控制码标记，避免空白区域占满系统盘，并在编码图像和图层释放后删除。小型多帧图片的 Magick 回退路径以源文件大小、总解码像素和文字瓦片大小作严格上限，超限返回 `ANNS0002`。

针对带文字笔记的 TIFF 直接报 `ANNS0003` 的情况，导出器现按原图的色彩解释和位深转换文字、画笔图层。CMYK 图像有内嵌 ICC 时只把该配置用于小图层的颜色转换，不对整个大图做一次全量转换；没有内嵌 ICC 时使用 libvips 的 CMYK 配置。灰度及 16 位图像也转换图层的颜色与透明度范围，合成后明确检查通道数。不能安全保持原有色彩布局的格式返回 `ANNS0002`，不会仅凭通道数裁切并继续写出颜色错误的图片。小型单帧文件若流式编码器失败，可在源文件大小与解码像素的限制内改用 Magick，且将文字瓦片一并合成。`ANNS0003` 现在附带底层编码器的错误文本，便于判断磁盘、编码器及文件内容问题。

## fd 单文件发布

fd 的发布配置关闭 ReadyToRun，并启用单文件内容提取。已有故障转储显示，fd 版本在进入 `ImageLoader.Load` 方法体之前，于 .NET 运行时预备阶段异常退出；sc 单文件和非单文件版本没有该故障表现。修改仅作用于 fd 发布配置。fd 仍需要目标机器安装对应的 .NET Windows Desktop Runtime。
